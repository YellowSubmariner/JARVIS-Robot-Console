# JARVIS Robot Console

Windows 机械臂现场工具：监看两路相机、录制手柄示范、自动整理候选训练样本，再回看检查和导出。主项目见 [JARVIS 项目仓库](https://github.com/YellowSubmariner/JARVIS-An-Embodied-Co-Creator)。

**日常使用：填写一次任务 → 开始录制 → 用现有手柄完成取放 → 标记结果 → 继续下一条。** 软件在后台整理刚录完的数据，最后到“样本库”集中检查和导出。夹爪中间开度按连续数值保存。

录制、整理、回看和导出普通数据包都不需要 π0.5 权重、GPU 或云算力。转换为 LeRobot 需要另行准备数据转换环境，也不加载模型。当前为数据采集预览版；离线测试不等于已在实机上验证。

## 下载

从本仓库 [Actions](https://github.com/YellowSubmariner/JARVIS-Robot-Console/actions) 选择最新成功的构建，下载 `JARVIS-Robot-Console-dataset-preview-windows-x64`。构建产物在保留期内可下载，可能需要登录 GitHub。解压后运行 `JARVIS_Robot_Console.exe`，保留同目录的 `_internal`。

旧的 `recording-preview` 构建没有样本库；[v0.1.0 Release](https://github.com/YellowSubmariner/JARVIS-Robot-Console/releases/tag/v0.1.0) 只有相机监看。

## 首次设置

1. 连接机械臂和两路相机，在软件中确认画面正常。一次采集期间固定相机位置和分辨率。
2. 打开“示范录制”，在“Kortex Python”处选择已经安装兼容 `kortex_api` 的 Python 环境中的 `python.exe`。软件会记住路径；相机监看本身不需要该环境。
3. 首次录制时输入机械臂密码。密码保存在当前 Windows 账户的凭据管理器中，之后使用相同机器人地址和用户名时不必重复输入；可通过页面按钮更新或清除。
4. 选择数据保存目录，留足磁盘空间。两路相机逐帧存 JPEG；占用随分辨率和时长变化，应先录短样本实测。

## 录制示范

1. 输入本次任务，例如“把红色积木放进盒子”。同一任务连续录制时不必重复填写；换任务时修改文字。
2. 点击“开始录制”，等待页面明确显示可以开始示范，再操作现有手柄或控制程序。
3. 完成取放后，机械臂和夹爪稳定停留约 1 秒，再点击成功结束。失败或有人介入时如实选择对应结果。
4. 等待原始记录保存完成，然后继续下一条。软件自动在后台整理候选样本；整理失败仍保留原始记录。
5. 先录 5–10 条试采样，检查数据后再大批量录制。

软件只读取相机和机械臂状态，不发送机械臂运动命令。每条示范保存为一个独立文件夹，包含任务与结果、两路相机图像及时间索引、七关节和夹爪的实际反馈。默认保存在程序目录的 `recordings/` 中，也可以自行选择位置；请保留整个文件夹。

软件会尝试记录手柄事件，但当前尚未验证能收到手柄按键或原始控制命令。保存的是原始采集数据；密码不会写入采集文件。请不要将现场视频、设备记录或密码上传到代码仓库。

## 检查与导出

1. 进入“样本库”。“等待检查”表示自动检查通过，还需要人工回看。
2. 选择一条示范，点击“查看与检查”，拖动时间滑块查看两路图像、七关节和连续夹爪数值。
3. 检查画面时序、位置标签适用性和稳定终态后，逐项确认并保存检查结果。不能只凭“录制成功”认定可用于训练。
4. 点击“导出已检查样本”，导出独立的训练、验证、测试清单及所需图片。按整条示范划分，避免同一条示范的相邻帧进入不同集合。至少 3 条是三个集合均非空的技术下限，远不足以说明训练数据量够用。
5. 可先备份这个普通数据包。准备好独立转换环境后，再点击“转为 LeRobot…”选择数据包和该环境的 Python；也可以把数据包搬到云端转换。

失败、人工接管、不完整录制，以及时间缺失、关节角异常、末尾未稳定的示范不会自动进入导出。修改原始文件或重新整理后，旧检查记录会失效。导出或格式转换期间暂不开始新录制，以免争抢磁盘。

## 标签到底是什么

默认按 20 Hz 整理：输入是当前可获得的两路画面、七关节角与夹爪实测位置；候选动作是下一采样时刻的七关节与夹爪实测位置。关节转换为弧度，夹爪百分比转换成 0–1 连续数值，例如 35% 保留为 0.35。

**下一时刻实测位置不是原控制命令。** 特别是夹到物体时，实测开度不等于请求的闭合目标或夹持力。训练和部署前必须验证位置目标能否让你们的控制器复现动作；若不适用，应从原控制程序记录真正的连续夹爪目标。

自动对齐使用同一电脑的接收时间，不能消除相机缓存或网络延迟，也不能证明相机曝光同步。完整规则、文件格式和转换环境配置见 [数据整理与 LeRobot 导出说明](docs/DATA_PIPELINE.md)。完整训练方案见主项目的 [π0.5 数据采集与微调部署指南](https://github.com/YellowSubmariner/JARVIS-An-Embodied-Co-Creator/blob/main/docs/PI05_Kinova_%E6%95%B0%E6%8D%AE%E9%87%87%E9%9B%86%E4%B8%8E%E5%BE%AE%E8%B0%83%E9%83%A8%E7%BD%B2%E6%8C%87%E5%8D%97.md)。

## 从源码运行

使用 Windows 64 位 Python 3.13：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

机器人录制所需的 Kortex Python 环境需单独准备。

离线测试使用模拟反馈与图片，不连接机器人：

```powershell
python -m unittest discover -s tests -v
```

Kortex 读取进程、应用本身、LeRobot 转换进程使用各自环境，不要把不兼容的依赖混装进同一个环境。

界面统一使用 Windows 自带的“微软雅黑 UI”，标题、正文与辅助文字保留清晰的字号层级。字体集中在 `jarvis_camera/typography.py`，列表行高随字体和显示缩放计算；系统原生文件选择框沿用 Windows 字体。会显示窗口的界面回归测试默认不运行，仅在专用测试桌面设置 `JARVIS_RUN_VISIBLE_UI_TESTS=1` 后启用。
